# IBM 5160 BIOS 10JAN86 — POST 301 / 601 / F1 (byte-accurate)

**ROM:** `/mnt/TurboDebugger/subprojects/iron86/tests/images/hdc-proof/xt5160_10jan86_64k.bin`  
**Size:** 65536  
**SHA256:** `cfa8f89cc4e765901321a26e619bde346740c41eefddd5beb37314e9dffd107e`  
**Load:** file offset 0 = `F000:0000` = phys `0xF0000`. Reset `FFFF:0000` / file `0xFFF0`.  
**Date / model:** `01/10/86` at `F000:FFF5`, model byte `FB` at `F000:FFFE`, checksum byte `A3` at `F000:FFFF` (8-bit sum of all 64K = 0).  
**Listing cross-check:** IBM PC XT BIOS V2 (01/10/86) `POST.ASM` / `KEYBRD.ASM` / `DSKETTE.ASM` at `/mnt/linux/docs/research/IBM-PC-BIOS/IBM PC XT/XT BIOS V2/`. Labels below are from that listing; **bytes and CS:IP are from this ROM**.

**Convention:** `F000:IP` = file offset `IP`. Dummy-stack / Capstone physical targets like `0xff9e3` mean `F000:F9E3`.

## 0. Verdict (read this first)

| Symptom | What it is | What it is not |
|---------|------------|----------------|
| **301** | Keyboard POST (`TST12` / `KBD_RESET`). Printed by `E_MSG` with `SI = F000:E98A` (`" 301\r\n"`). | Not the F1 key. Not BAT-on-port-60 as a standalone test — BAT is checked **after** IRQ1 sets `[40:6B]` bit 1. |
| **F1 prompt** | Summary halt when `BP ≠ 0`. `BP` is the error-string pointer saved by `E_MSG` (`MOV BP,SI`). Waits via **real** INT 16h AH=00 for scancode `3Bh`. | **Not** a third hardware error. Not a third keyboard test. |
| **601** | Floppy POST (`SEEK` to track 34 never got IRQ6 / `[40:3E]` bit 7). Printed with `SI = F000:E990` (`"601\r\n"`). | Independent of 301. Same `E_MSG`/`P_MSG` printer. |

`P_MSG` (`F000:F997`) stops at the first LF (`0x0A`). The bytes at `E98A` are `20 33 30 31 0D 0A 36 30 31 0D 0A` = `" 301\r\n601\r\n"`. If `SI=E98A` the screen shows **301 only**. 601 appears only when `SI=E990`.

## 1. `KBD_RESET` — `CALL F000:F9E3`

Two callers (near CALL, rel16 lands on `F9E3`):

| CS:IP | bytes | when |
|-------|-------|------|
| `F000:E22F` | `E8 B1 17` | Early config: MFG jumper / extended keyboard (`CMP BL,EAh` / `AAh` / `65h`). **Does not print 301.** |
| `F000:E3E4` | `E8 FC 15` | `TST12` keyboard POST. **This is the 301 path.** |

### 1.1 Exact body (file `0xF9E3`)

IBM name: `KBD_RESET`. `SP_TEST` (MFG bootstrap) enters at `F9F0` (skips the 20 ms clock-low pulse).

```
F000:F9E3  B0 08           MOV  AL,08h          ; PB: KBD clock line LOW
F000:F9E5  E6 61           OUT  61h,AL          ; 8255 Port B
F000:F9E7  B9 56 29        MOV  CX,2956h        ; ~20 ms @ 4.77 MHz
F000:F9EA  E2 FE           LOOP F9EA
F000:F9EC  B0 C8           MOV  AL,C8h          ; clock + enable HIGH (PB7=1 ack)
F000:F9EE  E6 61           OUT  61h,AL
; SP_TEST entry:
F000:F9F0  B0 48           MOV  AL,48h          ; clock HIGH, keyboard enable LOW
F000:F9F2  E6 61           OUT  61h,AL
F000:F9F4  B0 FD           MOV  AL,FDh          ; IMR: unmask IRQ1 only (bit 1 = 0)
F000:F9F6  E6 21           OUT  21h,AL
F000:F9F8  C6 06 6B 04 00  MOV  BYTE [046B],0   ; INTR_FLAG = 0  (DS = 0000)
F000:F9FD  FB              STI
F000:F9FE  2B C9           SUB  CX,CX           ; timeout = 65536 loops
F000:FA00  F6 06 6B 04 02  TEST BYTE [046B],02h ; bit 1 = IRQ1 seen by dummy ISR
F000:FA05  75 02           JNZ  FA09            ; got IRQ1
F000:FA07  E2 F7           LOOP FA00            ; else spin; CX=0 on timeout
F000:FA09  E4 60           IN   AL,60h          ; ALWAYS read Port A (even on timeout)
F000:FA0B  8A D8           MOV  BL,AL           ; save scan/BAT in BL
F000:FA0D  B0 C8           MOV  AL,C8h          ; clear keyboard (PB7 ack)
F000:FA0F  E6 61           OUT  61h,AL
F000:FA11  C3              RET
```

Port-B sequence on the 301 path is therefore **`OUT 61, 08` → delay → `OUT 61, C8` → `OUT 61, 48`**, then **`OUT 21, FD`**, **`MOV [046B],0`**, **`STI`**, wait **bit 1 of `[046B]`**, **`IN 60`**, **`OUT 61, C8`**.

`[046B]` is BDA `40:6B` `@INTR_FLAG` (POST dummy-interrupt flag). It is **not** written by the real INT 9 handler.

## 2. `TST12` caller — `F000:E3C8` … `E40D`

PIT channel 0 is programmed to mode 3 **immediately before** the keyboard test (so IRQ0 can fire at ~18.2 Hz once unmasked later; during `KBD_RESET` IRQ0 is still masked by IMR=`FDh`).

```
F000:E3C4  B0 FF           MOV  AL,FFh
F000:E3C6  E6 21           OUT  21h,AL          ; mask all IRQs
F000:E3C8  B0 36           MOV  AL,36h          ; PIT ch0, lobyte/hibyte, mode 3
F000:E3CA  E6 43           OUT  43h,AL
F000:E3CC  B0 00           MOV  AL,00h
F000:E3CE  E6 40           OUT  40h,AL          ; divisor 0000 = 65536
F000:E3D0  E6 40           OUT  40h,AL
F000:E3D2  B0 99           MOV  AL,99h          ; 8255: A,C=in B=out
F000:E3D4  E6 63           OUT  63h,AL
F000:E3D6  A0 10 04        MOV  AL,[0410]       ; EQUIP_FLAG low
F000:E3D9  24 01           AND  AL,01h          ; SW1-1 / IPL-diskette bit
F000:E3DB  74 30           JZ   E40D            ; skip kbd test if bit0=0
F000:E3DD  80 3E 12 04 01  CMP  BYTE [0412],1   ; MFG_TST
F000:E3E2  74 29           JZ   E40D            ; skip in manufacturing mode
F000:E3E4  E8 FC 15        CALL F9E3            ; KBD_RESET
F000:E3E7  E3 1E           JCXZ E407            ; (1) timeout → 301
F000:E3E9  B0 49           MOV  AL,49h          ; enable keyboard
F000:E3EB  E6 61           OUT  61h,AL
F000:E3ED  80 FB AA        CMP  BL,0AAh         ; (2) BAT must be AAh
F000:E3F0  75 15           JNZ  E407            ; fail → 301
; stuck-key probe
F000:E3F2  B0 C8           MOV  AL,C8h
F000:E3F4  E6 61           OUT  61h,AL          ; clr kbd, clk high
F000:E3F6  B0 48           MOV  AL,48h
F000:E3F8  E6 61           OUT  61h,AL          ; enable, clock in next byte
F000:E3FA  2B C9           SUB  CX,CX
F000:E3FC  E2 FE           LOOP E3FC            ; delay
F000:E3FE  E4 60           IN   AL,60h          ; (3) second IN 60h
F000:E400  3C 00           CMP  AL,00h
F000:E402  74 09           JZ   E40D            ; 00 = no stuck key, continue
F000:E404  E8 51 15        CALL F958            ; XPC_BYTE — print scan in hex
F000:E407  BE 8A E9        MOV  SI,E98Ah        ; SI → " 301\r\n"
F000:E40A  E8 69 15        CALL F976            ; E_MSG (also MOV BP,SI)
F000:E40D  1E              PUSH DS              ; F7: install real IRQ vectors
```

### 2.1 Confirmed 301 fail conditions (numbered)

Keyboard POST is skipped (no 301 possible from this test) if `EQUIP_FLAG` bit 0 is 0 **or** `MFG_TST==1`.

Otherwise **301 is printed** (`SI=E98A`, `CALL E_MSG`) when:

1. **`JCXZ E407`** (`E3E7 E3 1E`) — `KBD_RESET` timed out. `[046B]` bit 1 never set. Dummy ISR never recorded IRQ1. Typical emulator causes: IRQ1 never asserted after `OUT 21,FD`; IRQ1 fired **before** `MOV [046B],0` (lost); IRQ0 (or another IRQ) occupied the dummy so `[046B]` got `01h`/`FFh`/other, not bit 1.
2. **`CMP BL,0AAh` / `JNZ E407`** (`E3ED 80 FB AA` / `E3F0 75 15`) — IRQ1 happened, but the byte latched in `BL` from `IN 60h` is not BAT `AAh`.
3. **Stuck key:** second `IN 60h` (`E3FE E4 60`) then `CMP AL,00h` / `JZ E40D` (`E400 3C 00` / `E402 74 09`). Non-zero → `CALL XPC_BYTE` (print the scan code in hex) then **fall through** into `E407` and print 301.

There is no fourth 301 compare. F1 is later and separate.

## 3. Dummy ISR `D11` — `F000:FF23`

Installed for **all 32 IVT slots** at `E1F6` (`MOV AX,FF23h` / `STOSW` / `MOV AX,CS` / `STOSW` / `LOOP`, CX=32). Replaced for IRQ 0–7 at `F7` (`E40D`) from `VECTOR_TABLE` at `FEF3`. Until then, **IRQ0 and IRQ1 both hit `D11`**.

```
F000:FF23  1E              PUSH DS
F000:FF24  E8 EB FA        CALL FA12            ; DDS: DS = 0040h
F000:FF27  50              PUSH AX
F000:FF28  B0 0B           MOV  AL,0Bh          ; OCW3: read ISR
F000:FF2A  E6 20           OUT  20h,AL
F000:FF2C  90              NOP
F000:FF2D  E4 20           IN   AL,20h          ; ISR bitmask
F000:FF2F  8A E0           MOV  AH,AL           ; AH = ISR
F000:FF31  0A C4           OR   AL,AH
F000:FF33  75 04           JNZ  FF39            ; hardware in-service?
F000:FF35  B4 FF           MOV  AH,FFh          ; no ISR bit → software/stray
F000:FF37  EB 0A           JMP  FF43
F000:FF39  E4 21           IN   AL,21h          ; IMR
F000:FF3B  0A C4           OR   AL,AH           ; mask the in-service level
F000:FF3D  E6 21           OUT  21h,AL
F000:FF3F  B0 20           MOV  AL,20h          ; EOI
F000:FF41  E6 20           OUT  20h,AL
F000:FF43  88 26 6B 00     MOV  [006B],AH       ; @INTR_FLAG = AH  (DS=40 → 40:6B)
F000:FF47  58              POP  AX
F000:FF48  1F              POP  DS
F000:FF49  CF              IRET                 ; also DUMMY_RETURN
```

### 3.1 What `AH` is (IRQ0 vs IRQ1)

`AH` is the **8259 ISR register**, a **bitmask**, not an IRQ index number.

| Who won the dummy | ISR / `AH` | `[40:6B]` | `KBD_RESET` `TEST [046B],02h` |
|-------------------|------------|-----------|-------------------------------|
| IRQ0 (timer)      | `01h`      | `01h`     | **fail** (bit 1 clear) → 301 timeout |
| IRQ1 (keyboard)   | `02h`      | `02h`     | **pass** |
| IRQ6 (floppy)     | `40h`      | `40h`     | fail |
| no hardware ISR   | `FFh`      | `FFh`     | pass (`FFh & 02h ≠ 0`) — but then `IN 60` is whatever is on Port A |
| both IRQ0+IRQ1 pending | typically `01h` (IRQ0 higher priority) | `01h` | **fail** |

`KBD_RESET` requires **bit 1**. A live IRQ0 during the wait (IMR=`FDh` still allows IRQ0? **No** — `FDh` = `11111101b` masks bit 0, unmasks bit 1). IRQ0 is **masked** during `KBD_RESET`. IRQ0 steal is therefore **not** from IMR=`FD`; it happens if:

- IMR is not actually `FD` (wrong PIC), or
- IRQ0 is already in-service / IRR races the `OUT 21,FD` → dummy runs **before** `MOV [046B],0` and the following `MOV` clears a good IRQ1 flag, or
- a **hot interrupt** left `[046B]` stale (the hot-int test at `E374` zeros it while IMR=0 then IMR=`FF`).

The one-instruction gap `OUT 21,FD` / `MOV [046B],0` is real (`F9F6` then `F9F8`). If IRQ1 is dispatched on the `OUT` and dummy writes `[046B]=02` **before** the MOV, the MOV **clears** the success flag and the wait times out → 301.

## 4. F1 resume — `F000:E600` / `E611`

`E_MSG` (`F976`) does `MOV BP,SI` **before** printing. `BP` is therefore a **non-zero pointer to the error string** (e.g. `E98A` for 301, `E990` for 601, `F8CC` for 101). It is **not** a hardware error code.

After floppy POST, keyboard buffer init, and `OUT 21, FCh` (unmask IRQ0+IRQ1):

```
F000:E5FA  E4 21           IN   AL,21h
F000:E5FC  24 FC           AND  AL,FCh          ; enable timer + keyboard
F000:E5FE  E6 21           OUT  21h,AL
F000:E600  83 FD 00        CMP  BP,0000h        ; any E_MSG since BP was zeroed?
F000:E603  74 18           JZ   E61D            ; no error → one short beep
F000:E605  BA 02 00        MOV  DX,0002h        ; 2 short beeps
F000:E608  E8 9A 13        CALL F9A5            ; ERR_BEEP
F000:E60B  BE 69 E7        MOV  SI,E769h        ; "ERROR. (RESUME = \"F1\" KEY)\r\n"
F000:E60E  E8 86 13        CALL F997            ; P_MSG (does NOT change BP)
F000:E611  B4 00           MOV  AH,00h          ; INT 16h function 0 (blocking read)
F000:E613  CD 16           INT  16h
F000:E615  80 FC 3B        CMP  AH,3Bh          ; F1 make scancode
F000:E618  75 F7           JNZ  E611            ; ignore anything else
F000:E61A  EB 0E           JMP  E62A            ; continue POST (printer/RS232/boot)
```

String at `E769` (file `0xE769`):

```
45 52 52 4F 52 2E 20 28 52 45 53 55 4D 45 20 3D 20 22 46 31 22 20 4B 45 59 29 0D 0A
ERROR. (RESUME = "F1" KEY)\r\n
```

By this point `F7` has already installed the **real** INT 9 (`E987` → `KB_INT_1` at `0D78`) and INT 16 (`E82E` → `KEYBOARD_IO_1` at `0C57`). F1 is a **normal key read**, not dummy-ISR.

`BP` was zeroed at `E1A4` (`SUB BP,BP`) after the KBX restore. Every `E_MSG` sets it. F1 is **only** the summary wait.

If `EQUIP_FLAG` bit 0 is 0, `E_MSG` itself **CLI/HLT**s (`F986`) instead of returning — no F1 prompt in loop-on-POST / no-floppy chamber mode.

F000:E5C6  0B F6           OR   SI,SI
F000:E5C8  74 06           JZ   E5D0            ; no prior error
F000:E5CA  BE 90 E9        MOV  SI,E990h

IRQ6 handler (after `F7` installed `VECTOR_TABLE`; INT 0Eh = `EF57` → `DISK_INT_1` at `0BC4`):

```
F000:0BC4  FB              STI
F000:0BC5  50              PUSH AX
F000:0BC6  1E              PUSH DS
F000:0BC7  E8 48 EE        CALL FA12            ; DS=40
F000:0BCA  80 0E 3E 00 80  OR   BYTE [003E],80h ; @SEEK_STATUS bit 7 = INT_FLAG
F000:0BD2  E6 20           OUT  20h,AL          ; EOI (AL=20)

```

```
F000:0B17  F6 06 3E 00 80  TEST BYTE [003E],80h
F000:0B1C  75 0C           JNZ  0B2A            ; got IRQ6
F000:0B1E  E2 F7           LOOP 0B17

```

If IRQ6 stays masked, or `DISK_INT_1` never runs, bit 7 of `[40:3E]` never sets → 601.

## 10. Warm start / `--fast-post` (E199 is **not** 1234h)

Session lore said “fast-post `E199` (warm 1234h)”. **This ROM:**

## 12. POST order (condensed, this ROM)

```
FFFF:0000  EA 5B E0 00 F0     JMP F000:E05B     RESET
E05B  flags/regs test → HLT on fail
E0AC  NMI off, 8255, checksum 64K (F8BF), DMA+PIT1 refresh
E175  CMP BX,1234h warm → skip STGTST
E1DE  8259 ICW1/2/4, IMR=FF
E1F6  IVT[0..31] = D11 (FF23)
E211  IN 62h SW1 mux → EQUIP_FLAG
E22F  CALL KBD_RESET (MFG / KBX, not 301)
E260  INT 10 init MDA then CGA from SW
E2C3  NMI stub
E2DD  1234h skip video RAM
E35B  8259 IMR test; hot-int; timer 0 too-slow/too-fast (101 + HLT)
E3C8  PIT ch0 mode 3
E3E4  CALL KBD_RESET → 301 paths
E40D  F7: copy VECTOR_TABLE (real IRQ0/1/6, INT 10–1A)

E4A1  1234h skip extra RAM → ROM_SCAN

E56A  floppy 601
E5D0  kbd buffer; OUT 21,FC
E600  CMP BP,0 → F1 wait

```

## 13. Open emulator implications (static only; not run here)

1. **301 timeout** if IRQ1 does not set `[046B]` bit 1 between `F9F8` and `FA07` wrapping CX.
2. **301 lost-IRQ** if dummy runs on the `OUT 21,FD` and `MOV [046B],0` clears bit 1.
3. **301 BAT** if `IN 60` after PB7 `C8` ack is not `AAh` (PB7 must not destroy the latched BAT before `FA09`).
4. **301 stuck-key** if a second byte is already on Port A after the delay.
5. **F1** only after a successful `E_MSG` (`BP≠0`) and with **real** INT 9/16 installed; scancode `3Bh` in **AH**.
6. **601** if IRQ6 never sets `[40:3E]` bit 7 during `WAIT_INT` (`0B17`).
