## Summary

Presets, `--hdc` / `--hdc-rom` / `--no-fast-post`, 8086 prefetch default 6, BIOS HLT ≠ session halt, and `pit_poll` IRQ0 are real. `DIR C:` as an empty FAT12 root is consistent with the `ff83f30` claim; FORMAT persist and cold POST are still open. Agent control is the weak spot: `run` toggles F9, `getip`/`status` always report `stop=1` (`REX_STOP_STEP`) while F9 is live, default sockets steal each other, and headless `unpause`/`pause` do not drive the CPU. Docs lag the binary: `docs/CLI.md` still omits tdx `--hdc` and claims floppy CHS is the old 8/1-else-9/2 heuristic; `man/tdx.1` still says prefetch default 4.

## Issues

### Issue 1 -- Severity: bug
- File: `src/rex/rex_sock.cpp:1363`
- Description: `rex_sock_listen` always `unlink(path)` then `bind`. A second `tdx` (or tdxview agent listen at `src/tdx/tdx_agent_sock.cpp:65`) silently steals `/tmp/tdx.sock`: the first process keeps a bound fd to an unlinked inode; new `tdxctl` talks to the second instance. If `bind` fails after unlink, the previous socket name is already gone. If `listen` fails after a successful bind (`rex_sock.cpp:1379`), the new sock file is **not** unlinked (tdxview’s agent path does unlink on listen fail). Combined with hardcoded defaults, two TDX windows are unsafe without manual `--sock`.
- Suggestion: default `--sock /tmp/tdx.<pid>.sock` (or refuse to unlink a live socket); unlink the new path if `listen` fails; keep `scripts/tdx-kill.sh` as the broom, not the only safety.
- Status: open

### Issue 2 -- Severity: bug
- File: `src/rex/rex_sock.cpp:1329`
- Description: Every agent reply, including `getip` and `status`, sets `"stop": (int)rex_session_stop_reason(s)`. After any successful insn `last_stop` is `REX_STOP_STEP` which is **1** (`include/rex/rex_types.h:59`). F9 run slices end on STEP (`src/dos/dos_machine.cpp:1449`, `:1554`). There is no `running` field; `ui.running` lives only in `tdx_ui.cpp:99`. Agents that treat `stop!=0` as paused will see `stop=1` while the guest is advancing. Matches the TODO note; this is the mechanism.
- Suggestion: report `running` from the UI/F9 flag (or a session flag set by `REX_UI_START_RUN` / cleared on pause). Keep `stop` as last reason; document `1 = STEP` in `tdxctl` help. Do not use `stop==0` as “is running”.
- Status: open

### Issue 3 -- Severity: bug
- File: `src/tdx/tdx_view.cpp:360`
- Description: tdxview F9 sends `{"cmd":"run"}`, which is `REX_UI_TOGGLE_RUN` (`src/rex/rex_sock.cpp:245`). If the CPU window (or `tdxctl unpause`) is already running, F9 in tdxview **pauses**. `key`/`type` correctly post `REX_UI_START_RUN` (`rex_sock.cpp:1161`, `:1209`).
- Suggestion: send `unpause` (or `F9` only when mirroring the CPU key). Same for any spectator path that means “go”.
- Status: open

### Issue 4 -- Severity: bug
- File: `src/tdx/tdx_main.cpp:92`
- Description: After parse, `--hdc` without a filled BIOS path prints `tdx: --hdc needs --bios or --preset ibm-xt` and exits 2. Parse already implies `ibm-xt` and calls `find_default_bios_rom` (`src/tdx/tdx_cli.cpp:405–418`). The error therefore means “default 5160 ROM not found”, not “you forgot `--preset`”. `--hdc --no-bios` hits the same check because `--no-bios` skips the fill (`tdx_cli.cpp:414`) even with `--preset ibm-xt`. `--no-bios --bios FILE` still loads ROM (`tdx_main.cpp:122`) — `--no-bios` is ignored.
- Suggestion: if `hdc` set and `bios` empty, say the ROM path was not found (`IRON86_XT_BIOS` / default 10JAN86). If `no_bios && !hdc.empty()`, say Xebec needs a 5160 ROM. If both `--no-bios` and `--bios`, error or let `--no-bios` win.
- Status: open

### Issue 5 -- Severity: bug
- File: `src/dos/dos_machine.cpp:1141`
- Description: `attach_hdc_rom` returns `REX_OK` when `load_hdc_rom_path` fails (log only). tdx then boots 5160 without ROS at C8000; `DIR C:` fails for a reason that looks like “HDD broken” rather than “ROS missing”. Missing default ROS with a NULL path also returns OK (`:1137`).
- Suggestion: return `REX_ERR_IO` when `--hdc-rom` was explicit or when `--hdc` is attached and no ROS mapped. Keep OK only for floppy-only `ibm-xt` with no `--hdc`.
- Status: open

### Issue 6 -- Severity: bug
- File: `subprojects/iron86/src/pc.cpp:2069`
- Description: FDC Write Data (`0x05`) and Write Deleted (`0x09`) complete with `st0=drv`, `st1=0` and **no** DMA-from-mem into the image. Guest COPY/saves believe the write worked; bytes never hit A:/B:. Read path (`0x06`) does DMA-to-mem (`pc.cpp:2001`). TODO lists Write as missing; returning success is worse than ST0 error.
- Suggestion: until DMA-from-mem exists, set ST0/ST1 to a write fault (or ignore-write with a clear log) so DOS does not report OK.
- Status: open

### Issue 7 -- Severity: bug
- File: `src/dos/dos_machine.cpp:1393`
- Description: Window title after AH=4Ch is still the last 4Bh name. `note_exec_from_dsdx` writes `exec_name`; nothing clears it on 4Ch/INT 20. `format_win_title` / tdxview `guest` JSON will keep showing `TANK.COM` (etc.) after the child exits. On the C++ INT 21 path, AH=4Ch also sets `halted` (`src/dos/dos_int.cpp:974`) so FloppyOS never returns to COMMAND — related TODO, separate from the title string.
- Suggestion: on AH=4Ch / INT 20, set `exec_name` to `COMMAND.COM` when a parent shell exists, else clear it so the title drops the child. Do not treat BIOS-path guest DOS 4Ch as session halt.
- Status: open

### Issue 8 -- Severity: bug
- File: `src/tdx/tdx_main.cpp:206`
- Description: Headless (`--no-ui`) never calls `rex_session_take_ui_cmd`. `tdxctl unpause` posts `REX_UI_START_RUN` and does nothing; without `--run` the loop only `usleep`s (`tdx_main.cpp:218`). With `--run`, every iteration calls `rex_session_run` again; `pause` sets `stop_req` but `run_until` clears it on entry (`src/dos/dos_machine.cpp:1528`), so pause cannot stick. Fine for `make test` fixtures; broken for a headless agent play path.
- Suggestion: honor `REX_UI_START_RUN` / `STOP` in the headless loop (a `running` bool, same as the UI). `--run` should mean initial unpause, not “ignore pause forever”.
- Status: open

### Issue 9 -- Severity: suggestion
- File: `src/tdx/tdx_main.cpp:200`
- Description: `--run` with the SDL UI runs `rex_session_run(s, 0)` (50M insns, wait-key parked) **before** `tdx_ui_run`, which then starts with `ui.running = false`. Help calls `--run` “headless-friendly”; with a window it burns POST/DOS then shows a paused CPU view. `--run` does not set F9-live.
- Suggestion: if UI, set `ui.running = true` (or post `REX_UI_START_RUN`) and skip the pre-UI 50M burst.
- Status: open
