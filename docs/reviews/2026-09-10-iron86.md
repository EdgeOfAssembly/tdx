# iron86 review 2026-09-10

HEAD `ff83f30` (`milestone/bios-flopfs-dir`). Scope: iron86 only (no source edits). CLI binary reports **0.21**.

## Summary

Xebec + INT 13 `DL>=80h` + host-disk refuse + 8259 fully-nested IRQ + XT BAT/IRQ1 delay are real and tested; `DIR C:` on empty FAT12 (tdx `ibm-xt` + DOS 3.31) matches the TODO and the M1TP screenshot. TODO is mostly honest about FORMAT C: / cold POST / FDC write. It over-claims PPI I/O nibble **0x0F = 544K** (`io_nibble` is never read). Two correctness gaps: HDC DMA-from-memory ignores the 8237 count, and standalone `iron86 --bios` never pulses `wall_clock_irq0` so BIOS PIT reload-0 IRQ0 is dead (tdx `pit_poll` is fine). Man pages still say prefetch default **4** and iron86 **0.20**.

## Issues

### Issue 1 -- Severity: bug

- File: `subprojects/iron86/src/hdc.cpp:692`
- Description: `dma_from_memory()` copies `buf_.size()` bytes from guest RAM and ignores `dma_->curr_count[ch]`. `dma_to_memory()` correctly does `min(buf.size(), remaining)` at line 672. A short DMA count (or a programmed count of `N-1` that does not match the DCB block count) still writes a full sector/track to the image via `finish_write()`. `curr_count` is then subtracted as `uint16_t` and can wrap.
- Suggestion: Use the same `remaining = curr_count+1` clamp as the read path; if `n < buf.size()`, do not `ok()` a full write (underrun / incomplete).
- Status: open

### Issue 2 -- Severity: bug

- File: `subprojects/iron86/src/main.cpp:739` (BIOS run loop); `subprojects/iron86/src/pc.cpp:1544`
- Description: BIOS programs PIT ch0 reload **0** (18.2 Hz). `pit_tick` deliberately does **not** raise IRQ0 when `ch.reload == 0` (`irq0_insn = (i==0 && ch.reload != 0)`), expecting `wall_clock_irq0()` ~55 ms. **tdx** calls that from `dos_machine::pit_poll` (`src/dos/dos_machine.cpp:2146`). **iron86** `main` never does. Standalone `iron86 --bios` therefore never ticks IRQ0/BDA `40:6C` after POST programs the timer. `DIR C:` was proven under tdx, not this loop. `--until-prompt` can still see `A>` if the guest does not wait on INT 8.
- Suggestion: Call `wall_clock_irq0()` on a 55 ms cadence in the `--bios` step loop (same policy as tdx), or document that CLI `--bios` has no system timer.
- Status: open

### Issue 3 -- Severity: suggestion

- File: `subprojects/iron86/src/pc.cpp:1089` and `pc.cpp:2149`; `tests/test_pc.cpp:151`
- Description: TODO marks PPI I/O nibble **0x0F = 544K** done. `io_nibble` is stored and unused. IN 62h returns SW1 low/high nibble (5160 E211 mux). Default DIP `0x2D` → low nibble **0x0D** (480K if a 5150 BIOS treated it as SW2). The unit test comment still says “0x0F → 544K” but expects `0x0D`.
- Suggestion: Either mux `io_nibble` onto PC0–3 for the 5150 personality when PB2 selects I/O RAM, or drop the 544K checkbox and the dead field. Fix the test comment.
- Status: open

### Issue 4 -- Severity: suggestion

- File: `subprojects/iron86/src/pc.cpp:2069`
- Description: FDC Write Data (05h) and Write Deleted Data (09h) complete with ST0=drive (success) and never DMA-from-memory or touch `floppy_[]`. DOS INT 13 floppy writes currently go through the C++ intercept (AH=03 RAM copy), so this is idle unless ROM/FDC is used directly. Still a silent-success stub.
- Suggestion: Return ST0=`0x80` (invalid) until write is implemented, or implement `fdc_dma_from_mem` + optional host persist (the TODO item).
- Status: open

### Issue 5 -- Severity: suggestion

- File: `man/iron86.1:1`, `man/iron86.1:139`; `include/iron86/cpu.h:222`; `man/tdx.1:119`

### Issue 6 -- Severity: suggestion

- File: `subprojects/iron86/src/pc.cpp:1138`
- Description: `enable_fast_post()` always writes BDA `40:75 = 1` (one HDD) even when no HDC is attached. Harmless for the XT+HDC play path; a floppy-only 5160 fast-post can advertise a missing fixed disk.
- Suggestion: Set `40:75` from `hdc_.attached()`.
- Status: open

### Issue 7 -- Severity: suggestion

- File: `subprojects/iron86/src/hdc.cpp:60`
- Description: `hdc_xebec::attach` `fopen(path, "r+b")` **then** `fstat` and reject `S_ISBLK`/`S_ISCHR`. CLI is safe because `pc::attach_hdc_path` (`pc.cpp:215`) refuses before `attach()`. A direct `attach("/dev/sda")` still opens the node writable for a moment (no write before close).
- Suggestion: `stat`/`fstat` before `fopen`, or `open(O_RDWR|O_NOFOLLOW)` + `fstat` + reject, then `fdopen`.
- Status: open

### Issue 8 -- Severity: suggestion

- File: `subprojects/iron86/src/hdc.cpp:88`; `src/config.cpp:118`
- Description: INI `cylinders/heads/spt` are unbounded `uint32`. `sector_count_ = cylinders * heads * spt` and `need = sector_count_ * 512` wrap; `image_.assign(need, 0)` can throw `std::bad_alloc` uncaught. Opcode 0Ch caps cyl≤1024 / heads≤16; INI does not.
- Suggestion: Reject zero and cap to Type-1-ish maxima (or a documented max) in `attach` and INI parse.
- Status: open
